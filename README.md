# ledger

进程内福利额度账本库（Go）。单组织 500 名固定员工，每期每人发放 10000 分，
金额只用整数分；不做目录、鉴权与持久化。

## 语义

- 第 p 期发放的资金只能在第 p、p+1 期使用。
- `Submit(emp, amount)`：新建待处理申请并立即预占，较早来源优先；可用不足时不改变状态。
- `Resolve(emp, claimID, decision)`：批准（预占转已消费）、拒绝或取消（释放预占）；终态不可再变。
- `Advance()`：全组织原子推进一期。待处理申请若任一资金来源过期则整笔自动取消：
  仍有效部分返还原来源，过期部分计入已过期；未预占的过期余额计入已过期；已消费不过期。
- `Snapshot()`：返回同一瞬间的全组织一致状态（期号、按来源拆分的四类金额、申请状态与来源分配）。

## 并发设计

- 员工级互斥锁 + 写时复制的不可变状态；单员工操作只触碰该员工。
- 全局仅有原子计数器（期号、版本时钟）与一个只登记读版本的小临界区，
  不覆盖资金计算、员工遍历或员工锁。
- `Advance` 只是原子推进期号；各员工的滚动在被触碰时确定性完成，
  因此单个员工被暂停不会阻塞其他员工或 `Advance`。
- `Snapshot` 使用 MVCC：登记读版本后逐员工读取已发布的最新历史版本（不加员工锁），
  再纯函数滚动到读到的期号，不会拼接不同时间的员工状态。

## 测试

```sh
go test -race ./...
```

测试通过包内钩子（`ledger.go` 中的 `testHook*` 变量）确定性地控制账本内部交错，
覆盖并发超限提交、并发裁决同一申请、裁决与跨期的两种交错次序、
快照一致性切点，以及员工暂停时其他操作的进展性。
